**Status:** this document records source review, feasibility and the native source reconciliation below. Integrated Xcode/Simulator verification is in progress; source presence is not a passing test or physical validation. “Feasible” in the source table remains a platform decision, not a claim of complete parity. The pinned imported-source baseline must not advance merely because this audit or an update check ran. Local signing configuration is outside this audit and must remain unstaged.

## Public API evidence and inference boundaries

- [Apple External Accessory](https://developer.apple.com/documentation/externalaccessory/) supports manufacturer-authorized MFi accessories; it does not establish authorization/protocol access for these headphones. The lack of an arbitrary public iOS RFCOMM socket is why the exact Android Sennheiser/Sony/Bragi/Soundcore transports cannot simply be transplanted.
- [CoreBluetooth advertisement retrieval keys](https://developer.apple.com/documentation/corebluetooth/advertisement-data-retrieval-keys) document manufacturer data when delivered. They do not promise Apple Continuity telemetry or ownership correlation. The conditional Apple-advert conclusion above is an explicit inference from that contract and the upstream random-address heuristic, not a claim that all Apple advertisements are categorically filtered.
- [CoreBluetooth peripheral interaction](https://developer.apple.com/documentation/corebluetooth/cbperipheral) and [opening LE L2CAP](https://developer.apple.com/documentation/corebluetooth/cbperipheral/openl2capchannel(_:)) support actual discovered services/characteristics/PSMs. Neither a catalogue name nor an RFCOMM service UUID supplies a BLE transport.
- [AVAudioSession currentRoute](https://developer.apple.com/documentation/avfaudio/avaudiosession/currentroute) exposes this app's route. It is not a public list of every paired headset or a global media/call observer.
